Replace Amiss's manual JSON implementation with Serde

This plan covers the checkout at `b19caeaf` on `wire/serde-projection-sources`, including the eight source files already modified when the audit began on 2026-09-12. `git pull` reported “Already up to date.” The audit left those edits intact. It examined the engine, bootstrap, specialist, controller and provider consumers, schemas, examples, tests, fuzz targets, and benchmarks.

Implementation status, 2026-09-12: the seven migration slices below are implemented. The hand-written tokenizer, custom JSON value enum, manual object decoder, old control-value decoder, and bounded-envelope implementation are deleted. Serde now owns syntax, closed document shapes, report projections, canonical escaping, and streaming CLI/fatal output. A small event visitor and deserializer adapters retain Amiss's stricter contract. The tables below record the original audit; implementation validation follows at the end.

The recommended destination is one Serde-based implementation of the Amiss JSON contract: `serde_json` owns JSON syntax, derived `Deserialize` owns document shapes, and derived or narrowly implemented `Serialize` owns projections. Remove the current parser, custom JSON value enum, manual object decoder, handwritten JSON writer, and conversion bridges. Keep explicit domain validation, strict-input policy, canonical ordering, and resource admission. Those requirements do not disappear when the parser changes.

This is a substantial migration across document producers and consumers. Converting only `json/read.rs`, or adding derives while keeping the existing getter-based decoders, would leave most of the duplication in place.

The Unicode ordering requirement comes from [RFC 8785, section 3.2.3](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2.3). Serde's [recursion-limit documentation](https://docs.rs/serde_json/1.0.151/serde_json/struct.Deserializer.html#method.disable_recursion_limit) also explicitly calls out recursive operations after parsing, including dropping a parsed value. A successful parse alone is not a stack-safety proof.

The audit did not reproduce an infinite loop or establish the cause of any reported stall. Inspection identifies avoidable work: `Obj::take` repeatedly searches and removes from a vector; the old parser sorts every object's members and the writer sorts them again; request writers validate by reparsing their output; semantic construction retains canonical sort keys alongside observations and reparses each observation. `codec::digest` now materializes the full canonical payload where the older digest path streams it. These are profiling targets, not measured end-to-end bottlenecks.

A release-mode probe parsed and dropped a 6,224,837-byte synthetic document seven times per implementation. Median times were 18.40 ms for the old parser, 23.76 ms for a strict Serde visitor prototype, and 20.35 ms for plain `serde_json::Value`. This small, single-machine experiment shows that changing libraries alone does not establish a performance improvement. Plain Serde also omits required checks, so it is not a compatible replacement baseline.

I recommend the following implementation decisions.

1. Use a shared strict Serde input boundary, with `serde_json::Deserializer::from_slice` and an explicit `end()` check. Admit the bounded byte buffer before decoding. A small recursive `DeserializeSeed`/`Visitor` should reject duplicate decoded keys before insertion, enforce safe integers, reject floating-number tokens, and enforce the 512-container ceiling. Every subtree must pass this policy, including values a later typed projection ignores. Prevalidate UTF-8 and handle BOM deliberately. Keep error information for profile violations under Amiss's control. This code consumes Serde events; it must not implement tokenization, escaping, surrogate assembly or number scanning.

   The simplest initial implementation builds a checked `serde_json::Value` and consumes it through Serde into a derived document type, without converting it back to bytes. This retains one JSON tokenization pass and removes the custom AST. It is appropriate for open payloads and provides a clear correctness reference for closed documents. Measure its memory and runtime before widespread rollout. If large closed documents fail the acceptance budget, use a policy-enforcing Serde deserializer adapter to construct their typed data directly. Prove that adapter against the same strict-value implementation before switching those paths; do not relax validation to get a faster benchmark.

   The isolated visitor prototype accepted depth 512 and rejected 513 on a 2 MiB thread stack in release mode, and exercised clone/drop for the accepted values. It also rejected nested and escaped duplicate keys and the tested forbidden numbers. It is a feasibility probe, not production-ready error handling or an exhaustive stack proof. Only disable Serde's default limit inside an implementation whose own recursion boundary is enforced. Test both engine-only and whole-workspace dependency features; `api` already enables `unbounded_depth`.

2. Verify the canonical received payload before converting it into a representation that can discard or normalize fields. Decode a shared raw envelope shape, validate its outer members, compute the digest over the checked payload value, then deserialize that payload into the document and apply its laws. Preserve the existing digest domain and NUL separator. For reports and unknown semantic observations, retain every field that belongs to the hashed value even when the consuming projection uses only a subset.

   For closed document types that are used to reconstruct their input, require the property `JCS(Serialize(Deserialize(value))) == JCS(value)` for every accepted value. Preserve presence where the existing grammar permits both omission and explicit null. Restore rejection where explicit null has always been invalid, including selector suffixes. Do not use defaults, aliases, skipped fields or normalization as a shortcut around this law. Constructors validate the same constraints as readers without serializing and reparsing themselves. Cached digests are derived state and do not accidentally become wire fields.

3. Derive shapes and retain domain rules as typed validation. Reuse existing domain types whenever their wire representation matches, and use a derived wire DTO plus `TryFrom` where private fields, cached digests or a different domain representation require it. Apply `deny_unknown_fields` to closed shapes and explicit tagged variants. Share small field adapters for required-nullable and optional-non-null members. Preserve byte-count versus character-count limits: for example, reasons currently count characters, while many identities and record fields count UTF-8 bytes.

   Keep cross-field laws explicit: OID/object-format agreement, role ordering and distinct repositories, projection/source compatibility, resource bounds and aggregate floor limits, time ordering, eligibility, binding digests, uniqueness and array ordering. Do not replace an ordered input array with a map before checking its order and duplicates. Audit every nested `garde` traversal and every unvalidated field. Avoid broad untagged fallbacks that turn malformed known observations into ignored unknown observations. Serde documents both [untagged-enum considerations](https://serde.rs/container-attrs.html#untagged) and the incompatibility of [flatten with deny_unknown_fields](https://serde.rs/attr-flatten.html).

4. Define canonical emission independently of ordinary JSON serialization. Use Serde's serializer for all punctuation, escaping, booleans and numeric output. For dynamic values, use a checked borrowing `Serialize` view that visits object members in UTF-16 order and rejects non-profile numbers. For fixed large report shapes and digest projections, derive serialization over fields in canonical order and serialize borrowed data directly. Keep this ordering contract under byte-golden tests. Do not serialize a whole report into a second generic tree merely to sort its fixed field names.

   Derived internally tagged enums need special attention: Serde can emit the tag before fields whose names must precede it canonically. Use the canonical value path for small such documents, or borrowed per-variant output views that place the tag in canonical order. Sorting only top-level struct declarations is insufficient. Arbitrary extension maps must also pass through the ordering view rather than a plain map serializer.

   Counting, digesting, bounded output and ordinary output should be `Write` sinks over the same emission path. Preserve the single trailing report LF, exact byte counts, failure propagation and the reserved fatal-output path. Validate dynamic or otherwise fallible data before beginning externally visible output. Generic `Serialize` permits floats and non-string map keys, so the canonical API needs a checked input boundary or a serialization guard; the current `canonical(&f64::NAN)` silently produces `null`.

   A generic JCS dependency needs a memory review before adoption. The inspected [serde-json-canonicalizer implementation](https://raw.githubusercontent.com/evik42/serde-json-canonicalizer/master/src/jcs.rs) stores each object's serialized property values in buffers before emitting the object. Its `to_writer` API therefore does not establish Amiss's fatal scratch bound. Prefer the narrow ordering views above for this integer-only contract; an external implementation can still serve as a test oracle for compatible inputs.

5. Make the diagnostic compatibility decision explicit. Preserve scanner-visible analysis codes, useful field/index paths, duplicate detection and all rejection behavior. Adopt truthful Serde detection locations for JSON syntax rather than promising byte-identical offsets from the deleted parser. The old parser's granular syntax kinds and exact offsets are public Rust API and have exact tests; changing them needs a documented API migration and intentional test updates. Some old distinctions are not available from Serde's public error API. Do not rebuild a lexer just to imitate them.

   Keep a narrow adapter for Serde's library-generated shape errors where necessary, test it against the locked version, and represent Amiss-owned validation errors with explicit kinds. The current message-prefix matching must not silently control authorization or validation. Buffered enums and in-memory deserialization can lack a meaningful source position: report that honestly while keeping the semantic field path. Record error-precedence expectations for inputs containing both a digest mismatch and a shape/domain defect.

6. Preserve open contracts and upstream formats deliberately. `report::validate_envelope` permits additive fields within supported compatibility; unknown semantic kinds are inert but remain part of the digest and ordering. Closed derived types must not accidentally close those extension points or discard their hashed content. Move known report and observation shapes into typed projections so consumers stop reimplementing field access. A central dispatch on an open observation's kind can select a derived decoder; ordinary per-field `.member()` chains should disappear.

   Provider HTTP responses, webhook payloads, Rustdoc, and controller persistence already use Serde in several places. Keep upstream integer ranges, extensibility and authentication rules specific to those contracts. Apply the Amiss strict profile where a boundary actually promises it, such as the relation registry. Preserve HTTP body admission and transport deadlines. The binary sealed-request frame still requires bounded reads and EOF verification; Serde cannot resolve a producer that leaves a pipe open. Audit such waits separately from JSON CPU time.

   Controller ledger/journal/artifact formats hash their existing encoded representations and often require exact reserialization equality. Their current field order is stored-data compatibility, even where the code calls it canonical. Route shared Amiss documents through the new wire codec without rewriting unrelated persisted bytes or changing journal versions. Preserve engine dependency boundaries and repository-I/O confinement throughout.

Implementation and verification record

The migration preserves published valid wire bytes and digests. Received payloads are hashed before typed normalization, dynamic object keys retain UTF-16 ordering, and strict input covers duplicates, unsafe numbers, trailing bytes, UTF-8, BOM, and the 512-container ceiling. Object/string-only adapters close Serde's alternate array and externally tagged enum spellings, including nested types buffered by tagged enums. Direct `from_value` and report-validation entry points also enforce the numeric profile now that callers can construct a general Serde value themselves.

Constructors and report-building APIs propagate serialization failures. Shared hashing and envelope-size checks no longer allocate canonical byte buffers, borrowed observation projections allocate no JSON tree, and ordinary/fatal output stops at the first I/O failure with the original error preserved. Embedded controls and semantic documents decode from existing values. JSON round trips remain in tests that deliberately exercise byte-level round trips and fixtures. Upstream mdBook numbers retain their separate Serde encoding; this is not a general JCS floating-point formatter. Rustdoc now checks EOF and retains a bounded typed decoder.

The Rust API changes intentionally: JSON objects, numbers, strings, and arrays use Serde's native representations; `Obj` and its helpers are gone; projection and report constructors return errors. Syntax diagnostics use Serde's detection point. For example, the second decoded key in `{"a":1,"a":2}` is detected at byte 9, and incomplete Unicode escapes can be reported as unexpected EOF before an invalid hex character. Rejection and scanner analysis codes remain covered independently of those library-level locations.

Regression tests were run against deliberately broken implementations and restored afterward. They detected normalized-payload hashing, UTF-8 key ordering, duplicate overwriting, excess depth, omitted EOF checks, nullable-field acceptance, object/array and enum-spelling confusion, changed observation field order, swallowed I/O error sources, eager iterator consumption after output failure, and direct-value numeric-profile bypasses.

Resource checks include the 100,000-page locale evidence and 200,000-result assessment boundaries, the maximal fatal envelope and 64 KiB scratch allowance, over-cap report refusal, the exact request byte ceiling, unread-pipe failure, and parsing/cloning/serializing/dropping depth 512 on a 2 MiB worker stack. No infinite loop was reproduced. The migration removes redundant work but does not establish an end-to-end speedup.

A bounded release benchmark used a 4,319,519-byte synthetic wire document and 20 samples with one iteration each. Median parse time was 7.887 ms, canonical emission 12.42 ms, counting 10.15 ms, and digesting 15.89 ms. These are single-run measurements, not a comparison with the earlier differently sized probe. The dense external-assessment benchmark fixture was repaired and its smoke check passes.

Validation completed with the workspace nextest suite and all-target Clippy with warnings denied, the standalone release fuzz smoke suite and all-target Clippy, both engine dependency-ban graphs, cargo shear, and the stable-edge similarity gate. Pre-commit hygiene ran against every tracked and newly added migration file using an isolated index. The pre-push stage passed with its dependency-audit hook run separately using network access and a writable temporary advisory cache; that full audit reported advisories, bans, licenses, and sources OK. The original checkout's index was not changed.

The final workspace run passed 1,830 tests with six explicitly skipped; the standalone release fuzz suite passed all eight smoke tests. The staged `amiss check --profile enforce` scan passed with exit 0 in an isolated checkout containing the complete change and the original pre-existing edits. Both pre-commit and pre-push checks are green, with the full dependency audit executed separately as described above.
